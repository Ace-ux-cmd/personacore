Overview

PersonaFlow is a plug-and-play SDK designed to eliminate the operational friction of producing, orchestrating, and managing AI responses. It manages the underlying complexity of stateful memory, multimodal processing, and system execution, allowing developers to deploy dependable AI capabilities without building and maintaining custom infrastructure from scratch.

By abstracting away Gemini-specific implementation details, common system challenges (such as multi-turn state persistence, speech recognition, vision handling, and automatic API key failover) are managed seamlessly behind one consistent, unified API.

Quickstart

Install the package, configure your system persona, and begin dispatching requests. The base execution pipeline operates out of the box with zero extra configuration.

01Installation
terminal 
npm install personaflow
02Initialization
index.js 
const AI = require("personaflow");

const ai = new AI({
    apiKeys: [
        process.env.GEMINI_API_KEY
    ],
    persona: `
You are an expert technical system assistant.
Provide direct, concise, and accurate responses.
`,
    historyLimit: 20, // Optional: memory storage cap
});

const response = await ai.handleMessage({
    userId: "12345",
    text: "Hello!"
});

console.log(response.text);
// 'Hello. How can I help you today?'

Features & Methods

handleMessage() is the core execution pipeline of PersonaFlow. All optional module configurations modify what handleMessage() can accept as inputs or return as outputs.

Primary Engine: handleMessage()

The handleMessage() method accepts a unified payload object. It does not enforce a rigid format—as long as at least one valid input parameter is supplied, the pipeline executes. Text input is not required if another input modality (such as an image or audio buffer) is provided.

Payload Schema
javascript 
const response = await ai.handleMessage({
  userId: "user_12345", // Required: Session identifier
  text: "Analyze this log.", // Optional: Text input
  image: imageBuffer, // Optional: Requires ai.useVision()
  voice: audioBuffer, // Optional: Requires ai.useSpeechRecognition()
});

Supported Input Modalities

Input Parameter Prerequisite Method Valid Payload Types
text None (Base Engine) string
image ai.useVision() Buffer, Base64 string, URL
voice ai.useSpeechRecognition() Buffer, ReadStream

Valid Payload Combinations

Because input requirements are flexible, any of the following dispatch signatures are valid:

  • Text-Only: { userId, text }
  • Image-Only: { userId, image }
  • Voice-Only: { userId, voice }
  • Multimodal: { userId, image, voice }, { userId, text, image }, etc.

Optional Features

Capabilities are strictly opt-in via progressive enhancement. Inactive feature modules are completely bypassed in the orchestrator pipeline, guaranteeing zero execution overhead.

optional-features.js 
// Enable persistent state via MongoDB
ai.useMemory(process.env.MONGODB_URL);

// Activate image payload decoding
ai.useVision();

// Activate audio-to-text transcription
ai.useSpeechRecognition();

// Activate audio synthesis with hybrid output rules
ai.useVoiceOutput({
    includeText: true,
    probability: 0.5
});
Method Capability & Scope System Behavior
useMemory(url) Persistent State Store Swaps default in-memory storage for MongoDB persistence.
useVision() Multimodal Vision Engine Enables decoding and processing of image binary payloads.
useSpeechRecognition() Audio Transcription (STT) Converts incoming voice buffers into normalized text prior to state execution.
useVoiceOutput(options) Speech Synthesis (TTS) Generates audio responses with configurable text/voice output probability.

Extension Modules

Extension methods extend the base capability of handleMessage() by hooking directly into the execution lifecycle.

progressive-config.js 
// Example: Progressive Configuration
ai.useMemory(process.env.MONGODB_URL);
ai.useVision();
ai.useSpeechRecognition();
ai.useVoiceOutput({ probability: 0.5 });

useMemory(url)

Configures persistent storage for session context using the internal MongoStore driver.

index.js 
ai.useMemory(process.env.MONGODB_URL);
  • Parameters:
    • url (string, required): MongoDB connection string (e.g., process.env.MONGODB_URL).
  • Connection Lifecycle: Connection is lazy. It initializes on the first saveMessage() or getHistory() call rather than at startup.
  • Error Behavior: If the Mongoose connection promise rejects, handleMessage() throws the error directly. getHistory() and deleteHistory() do not throw: they return the session data directly on success, or a { success: false, error } object on failure, so callers should check for a success field on the result rather than relying on try/catch.
index.js 
const history = await ai.getHistory("user_12345");

if (history && history.success === false) {
  console.error(history.error.code, history.error.message);
} else {
  console.log(history);
}

useVision()

Enables image payload ingestion for handleMessage().

index.js 
ai.useVision();
  • Parameters: None
  • Behavior: Unlocks the image field inside handleMessage() payloads, automatically formatting images for Gemini multimodal processing.

useSpeechRecognition()

Enables audio payload ingestion for handleMessage().

index.js 
ai.useSpeechRecognition();
  • Parameters: None
  • Behavior: Unlocks the voice field inside handleMessage() payloads, converting speech inputs into normalized text prior to prompt generation.

useVoiceOutput(options?)

Enables audio synthesis on model responses.

index.js 
ai.useVoiceOutput({
  includeText: true,
  probability: 1.0
});
  • Parameters:
    • options.includeText (boolean, default: false): Determines whether the text transcript is returned alongside the synthesized audio buffer.
    • options.probability (number, default: 0.5): A float between 0.0 and 1.0 defining the likelihood of generating voice output. At the default setting of 0, speech synthesis is bypassed entirely, returning standard text.

Constraints

This module is strictly scoped to text-to-speech (TTS) synthesis and does not perform downstream audio manipulation (such as pitch adjustment, format transcoding, or noise suppression). Any post-processing or client-specific audio transformations remain the responsibility of the host application.

API Key Rotation & Blacklisting

PersonaFlow features an automated key rotation engine that guarantees maximum uptime by handling upstream provider limits without manual try-catch loops.

javascript 
const ai = new AI({
  apiKeys: [
    process.env.GEMINI_KEY_1,
    process.env.GEMINI_KEY_2,
    process.env.GEMINI_KEY_3
  ]
});

Failover Lifecycle

When an API request is initiated via handleMessage(), the engine rotates through the key pool according to the following execution lifecycle:

  1. Pre-Flight Pool Check: The orchestrator checks the status of all configured API keys. If every key in the pool is currently marked as blacklisted, execution halts immediately with ALL_KEYS_UNAVAILABLE (metadata.keyIndex resolves to null).
  2. Rotatable Errors: If an active key encounters an error classified as rotatable (RATE_LIMIT, AUTH_ERROR, UPSTREAM_ERROR, or NETWORK_ERROR), the failing key is blacklisted and the orchestrator immediately retries the request with the next healthy key in the array.
  3. Non-Rotatable Errors: Invalid payloads or client-side bad requests (REQUEST_ERROR / HTTP 400 & 404) do not trigger key rotation. Execution fails immediately to prevent burning through remaining quota.

Audit & Telemetry Metadata

Every response exposes execution details so applications can monitor key pool health:

Field Location Description
apiKeyIndex success.metadata Index of the active key that successfully fulfilled the request.
rotated success.metadata true if key failover occurred at least once during execution.
keysTriedThisRequest success.metadata Total number of keys evaluated before receiving a valid upstream response.
keyIndex failure.metadata Index of the last key attempted before exhaustion or non-rotatable failure (null if all were blacklisted pre-flight).

Design Principles

Simplicity

A working AI should require only the essential configuration. Optional functionality stays optional.

Progressive Enhancement

Additional capabilities are enabled with .use...() methods. Apps that only need text conversations never have to configure vision, speech, or voice.

Platform Independence

PersonaFlow does not depend on Telegram, Discord, WhatsApp, Express, or any other platform. It focuses solely on conversational AI.

Human-First Conversations

An internal behavioral layer encourages natural conversational responses. Developers define the persona; PersonaFlow ensures the behavior stays consistent.

Single Responsibility

PersonaFlow is responsible for conversation management. Applications remain responsible for interfaces, authentication, scheduling, and platform-specific functionality.

Feedback Metadata

Every response exposes real-time execution metrics, including token consumption, response latency, exact model identifiers, and API key failover trails, giving developers full visibility into quota consumption and system health out of the box.

Non-Goals

These responsibilities belong to the application using the SDK, not the SDK itself:

  • Messaging platform integrations
  • Authentication
  • Scheduling & queuing
  • Typing indicators
  • Tool or function calling
  • Agent workflows
  • Retrieval-Augmented Generation (RAG)
  • Conversation summarization
  • User profiling
  • Rate limiting

Request Flow

A typical call to handleMessage() moves through validation, optional multimodal processing, the Gemini request, and response construction, in order:

1 Input Validation
2 Retrieve History
3 Speech Recognition optional
4 Vision Processing optional
5 Gemini Request
6 Voice Generation optional
7 Save Conversation
8 Build & Return Response

Module Reference

AI

The SDK's public interface. Stores configuration, exposes public methods, forwards requests to the orchestrator.

Orchestrator

Coordinates the request lifecycle: validates requests, determines execution flow, coordinates services, and returns the final response.

Memory Service

Retrieves and saves history, deletes history, applies the configured history limit, and selects the active storage backend.

Gemini Service

Builds Gemini requests, injects the configured persona, applies PersonaFlow's conversational behavior layer, manages API key failover, and returns AI responses with metadata.

Feature Services

Independent, optional services for vision processing, speech recognition, and voice generation.

Response Service

Constructs the standardized response object returned by the SDK.

Response Payloads & Metadata

handleMessage() returns a strongly-typed discriminated union based on the success field. Applications should branch directly on response.success to guarantee type safety and access operational metadata.

javascript 
const response = await ai.handleMessage({ userId: "user_123", text: "Hello" });

if (response.success) {
  console.log(response.text, response.metadata.responseTime);
} else {
  console.error(response.error.code, response.error.message);
}
1. Successful Response (success: true)

When execution completes without uncaught errors, handleMessage() returns the generated content along with full telemetry regarding token consumption, API key execution paths, and model specs.

json 
{
  "success": true,
  "text": "The operational output string...",
  "audio": "<Buffer ...>",
  "metadata": {
    "tokenUsage": {
      "promptTokenCount": 42,
      "candidatesTokenCount": 128,
      "totalTokenCount": 170
    },
    "apiKeyIndex": 1,
    "rotated": true,
    "keysTriedThisRequest": 2,
    "responseTime": 348,
    "finishReason": "STOP",
    "historyLimit": 10,
    "model": {
      "text": "gemini-3.1-flash-lite",
      "speechRecognition": null,
      "voiceOutput": null
    }
  }
}

Field Reference Successful Response

Key Type Description
success boolean Always true on this branch of the union.
text string The generated text output. Always present by default; omitted entirely if useVoiceOutput({ includeText: false }) is configured.
audio Buffer Synthesized speech audio. Only present when useVoiceOutput() is enabled and voice generation was triggered for this response.
metadata.tokenUsage object Container for Gemini token accounting. Resolves to {} if the upstream API returns no usage data.
metadata.tokenUsage.promptTokenCount number Tokens consumed by the input prompt (persona, history, and the current message combined).
metadata.tokenUsage.candidatesTokenCount number Tokens consumed by the generated response candidate(s).
metadata.tokenUsage.totalTokenCount number Sum of prompt and candidate tokens for this request.
metadata.apiKeyIndex number Index of the API key that ultimately succeeded for this request.
metadata.rotated boolean true if automatic key failover occurred during this execution turn.
metadata.keysTriedThisRequest number Total count of API keys evaluated before a valid response was received.
metadata.responseTime number Total execution time for the request, in milliseconds.
metadata.finishReason string Gemini's reported reason for ending generation (e.g. "STOP").
metadata.historyLimit number The configured in-memory message cap in effect for this session at the time of the request.
metadata.model.text string | null Model identifier used for text generation. null if the text stage was not active.
metadata.model.speechRecognition string | null Model identifier used for speech-to-text. null unless useSpeechRecognition() processed input on this turn.
metadata.model.voiceOutput string | null Model identifier used for speech synthesis. null unless useVoiceOutput() generated audio on this turn.

Field Behavior & Rules

  • text vs. audio Payload Delivery:
    • Default (Text Only): text is always a string. audio is undefined.
    • Voice Output Active (useVoiceOutput): If includeText: false was set in the modifier configuration, text is omitted entirely from the return object, leaving only audio (Buffer). If includeText: true (default), both text and audio are populated.
  • Key Rotation Auditing:
    • apiKeyIndex: Reflects the exact index of the API key that succeeded.
    • rotated: true if automatic key failover occurred during this execution turn.
    • keysTriedThisRequest: Total count of API keys evaluated before receiving a valid response.
    • Note: In multi-stage requests (e.g., text generation followed by audio synthesis), rotation metadata reflects the final outbound API call executed in the chain.
  • tokenUsage Structure: Echoes Gemini usage statistics. If the upstream API returns no usage data, this resolves to an empty object {} rather than null.
  • model Map: Tracks active model identifiers utilized across pipeline stages. Inactive stages return null.
2. Failure Response (success: false)

If an operational or upstream error prevents fulfillment, handleMessage() catches the error internally and returns a structured failure object.

json 
{
  "success": false,
  "error": {
    "code": "RATE_LIMIT",
    "message": "Resource has been exhausted (e.g. check quota)."
  },
  "metadata": {
    "keyIndex": 2,
    "model": "gemini-3.1-flash-lite",
    "responseTime": 182
  }
}

Field Reference Failure Response

Key Type Description
success boolean Always false on this branch of the union.
error.code string Deterministic error domain identifier. See the Error Code Reference below for the full set.
error.message string Human-readable description of the failure, generally forwarded from the upstream provider or the internal validator that raised it.
metadata.keyIndex number | null Index of the last API key attempted prior to failure. null if the key pool was already exhausted before the request was issued (ALL_KEYS_UNAVAILABLE).
metadata.model string Model identifier that was targeted at the time of failure.
metadata.responseTime number Time elapsed before the failure was raised, in milliseconds.

Error Code Reference

The error.code field categorizes execution failures into deterministic error domain types:

Error code Cause / HTTP Status Failover Behavior
RATE_LIMIT HTTP 429 Automatically rotates key and retries if clean keys remain.
AUTH_ERROR HTTP 401 or HTTP 403 Blacklists key, automatically rotates, and retries.
UPSTREAM_ERROR HTTP 5xx Automatically rotates key and retries.
NETWORK_ERROR Connection-level failure (no HTTP response) Automatically rotates key and retries.
REQUEST_ERROR Invalid payload or HTTP 400 / 404 Non-rotatable. Fails immediately without burning other keys.
ALL_KEYS_UNAVAILABLE Pre-flight key pool exhaustion Fails immediately. All keys in the pool are currently blacklisted.
NO_AUDIO_RETURNED Synthesis stage failure Pipeline completed, but the speech model returned 0 audio bytes.
AUDIO_TRANSCODING_ERROR useVoiceOutput() synthesis stage failure Non-rotatable. Fails immediately; not a key-related failure.
STORAGE_ERROR useMemory() persistence stage failure Non-rotatable. Fails immediately; not a key-related failure.
Key Index Context: In failure responses, metadata.keyIndex specifies the index of the last key attempted prior to exhaustion/failure. If the pool was completely exhausted prior to issuing the request (ALL_KEYS_UNAVAILABLE), metadata.keyIndex resolves to null.

Failure Cases

PersonaFlow draws a hard line between two categories of failure: developer-side mistakes, which throw synchronously before any network or storage call, and operational or runtime failures, which resolve as a structured { success: false } object instead.

Throws (constructor / synchronous validation)

new AI(config)

  • No config object, or not an object
  • apiKeys missing, not an array, empty array, or contains a non-string/empty-string entry
  • persona missing or not a string
  • historyLimit provided but not a positive number

ai.useMemory(mongoUri)

  • mongoUri missing or not a string
  • (does not throw for a bad/unreachable URI. That fails later, structured, at first use.)

ai.useVoiceOutput(options)

  • probability provided but not a number, or outside 0 to 1
  • includeText provided but not a boolean

ai.handleMessage(request), all synchronous, before any model/storage call:

  • No request object
  • Missing/non-string userId
  • None of text/image/voice provided
  • image provided but not a Buffer
  • voice provided but not a Buffer
  • text provided but not a string
  • voice provided but useSpeechRecognition() was never called
  • image provided but useVision() was never called

ai.getHistory(userId, options) / ai.deleteHistory(userId, options)

  • Missing/non-string userId
  • (nothing else throws. A storage failure past this point resolves structured, per the fix above.)

Internal/lower-level throws that only matter if you're calling these classes directly (not through AI, which never lets these conditions occur):

  • ArrayStore/MongoStore constructor: historyLimit < 1
  • ArrayStore.saveMessage/MongoStore.saveMessage: missing userId, or message missing role/text
  • VisionService.buildImagePart: non-Buffer image
  • SpeechRecognitionService.transcribe: non-Buffer voice
  • audioTranscoder.parseSampleRate: unparseable mimeType. This is now caught inside voiceOutput.generate() and converted to a structured AUDIO_TRANSCODING_ERROR, so it no longer surfaces as a throw through handleMessage().
  • audioTranscoder.pcmToOggOpus: ffmpeg spawn/exit failure. Same, now caught and converted structured.

Does Not Throw: Resolves as { success: false, error, metadata }

  • Gemini call fails (rate limit, auth, upstream, network, bad request): RATE_LIMIT / AUTH_ERROR / UPSTREAM_ERROR / NETWORK_ERROR / REQUEST_ERROR
  • All configured keys currently blacklisted: ALL_KEYS_UNAVAILABLE
  • Gemini TTS returns no audio part: NO_AUDIO_RETURNED
  • Audio transcoding fails after successful TTS: AUDIO_TRANSCODING_ERROR
  • Storage backend fails (history fetch, or persisting a turn, in handleMessage; or any call to getHistory/deleteHistory): STORAGE_ERROR

Error Handling Rules

Failure mode When it applies
Throws an Exception Developer-side validation errors (e.g., missing parameters, invalid constructor options, malformed payloads). Execution halts synchronously prior to network dispatch.
Returns Structured Failure ({ success: false }) Operational and runtime failures (e.g., Gemini upstream errors, MongoDB connection drops, ffmpeg binary execution issues).

Each module validates its own input and throws descriptive errors. PersonaFlow does not silently ignore failures: errors propagate upward to the public API.

Storage Layer

PersonaFlow currently supports two storage implementations, both exposing the same interface so the Memory Service can switch between them transparently.

Backend Use case
Internal in-memory storage Default. No setup, history cleared on restart.
MongoDB storage Enabled via useMemory(url), persistent across restarts.

Storage Layer API

The Storage Layer provides direct state management utilities to inspect or modify session history outside of the automated handleMessage() pipeline. Both in-memory and persistent store drivers (like MongoStore) implement these underlying methods.

getHistory()

Retrieves recorded conversation history for a given session.

javascript 
const history = await ai.getHistory(userId, options?);

Parameters

Parameter Type Required Description
userId string Yes Session identifier associated with the stored state.
options.limit number No Number of recent messages to retrieve.
Behavior & Rules
  • Without limit: Returns the entire recorded history for the specified userId.
  • With limit: Returns only the most recent X messages from the tail of the message log.
javascript 
// Retrieve complete history
const fullHistory = await ai.getHistory("user_123");

// Retrieve only the 5 most recent messages
const recentHistory = await ai.getHistory("user_123", { limit: 5 });

deleteHistory()

Purges stored message history for a given session.

javascript 
await ai.deleteHistory(userId, options?);

Parameters

Parameter Type Required Description
userId string Yes Session identifier associated with the stored state.
options.limit number No Number of recent messages to purge from state.
Behavior & Rules
  • Without limit: Clears all history for userId, completely resetting session state.
  • With limit: Purges only the most recent X messages, preserving earlier conversation context.
javascript 
// Purge complete session state
await ai.deleteHistory("user_123");

// Roll back state by deleting the last 2 messages
await ai.deleteHistory("user_123", { limit: 2 });
Error Handling Note: If using useMemory(process.env.MONGODB_URL) and the underlying database connection fails or drops, getHistory() and deleteHistory() do not throw. They resolve with a { success: false, error } object instead, consistent with the rest of the SDK's operational-failure handling. Check the result's success field rather than wrapping these calls in try/catch.
